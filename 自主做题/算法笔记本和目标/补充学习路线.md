# NLP 算法基础补充学习路线

> 本文是对《NLP 算法基础与 CS224N 定向刷题指南》的补充。原题单适合作为**算法与工程直觉的辅助训练**，但不应替代 NLP 模型、训练和实验基础的学习。

## 1. 先明确目标与权重

如果目标是读懂并完成 CS224N 风格作业，推荐时间分配为：

| 学习部分 | 建议占比 | 达标标准 |
| --- | ---: | --- |
| 模型与训练主线 | 70% | 能从零实现、训练并调试一个小模型 |
| 定向算法题 | 20% | 能解释题目在 NLP 中的真实用途与边界 |
| 复盘与实验记录 | 10% | 能定位 shape、mask、数值稳定性和评估问题 |

原题单可保留，但定位改为“**NLP 工程算法补充题单**”。它解决的是序列处理、候选搜索、数据结构和边界条件的手感；真正让人能读懂模型代码的核心，仍是张量计算、损失函数、反向传播和完整训练循环。

## 2. 原题单的使用原则

### 值得优先保留

- **LC 72 / 1143**：理解动态规划、序列对齐与边界初始化；随后必须自己实现 Viterbi，才能连到 HMM/CRF。
- **LC 215 / 373**：理解 Top-K 截断和多路径候选维护；随后必须手写 top-k、top-p filter 与 beam search。
- **LC 208 / 139 / 140**：理解词典匹配、切分与搜索空间；随后阅读 BPE、WordPiece 和 Unigram Tokenizer 的差别。
- **LC 20 / 394**：作为 Stack/Buffer/Action 的入门，服务转移式依存句法分析。
- **LC 3 / 76 / 56**：作为文本窗口、span 和 chunk 后处理的练习。

### 应降低优先级或修正映射

| 原内容 | 调整建议 | 原因 |
| --- | --- | --- |
| LC 53 最大子数组和 → LSTM/GRU 门控 | 只当一般 DP/贪心练习 | 门控是可学习的参数化状态更新，不能用 Kadane 算法解释。 |
| LC 295 数据流中位数 → Top-P | 换成手写 top-p（nucleus）采样 | Top-P 依赖按概率排序与累计概率，不依赖中位数。 |
| Trie → 所有 Tokenizer 的核心 | 改为“词表检索/前缀约束生成的常见结构” | BPE 训练的关键是 pair 统计与 merge；Unigram/SentencePiece 也不以 Trie 为本质。 |
| LC 48/54 矩阵题 → Attention | 只做一题或不做 | 实际更重要的是 `reshape`、`permute`、broadcast、mask 和 batch 维对齐。 |

> 题单当前共有 19 题；若保留“20 题”表述，可新增“实现 `top_k_top_p_filtering`”这一实践任务，而非再加一道关联较弱的 LeetCode 题。

## 3. 必须补上的模型主线

每一个主题都应包含：**手写最小实现 → 单元测试 → 与 PyTorch 官方算子对照 → 训练一个小实验**。

### 模块 A：张量、概率与训练基础

1. 熟练标注并检查 shape：`[B, S, D]`、`[B, H, S, Dh]`、`[B, S, V]`。
2. 实现数值稳定的 `softmax`、`log_softmax` 与 `logsumexp`。
3. 从 logits 手写交叉熵；理解为什么训练中不能先取 `argmax`。
4. 用 PyTorch 完成一次 `forward → loss → backward → optimizer.step()`，并检查梯度、device 与 dtype。

**验收任务**：随机生成 logits 和标签，手写 cross entropy 与 `torch.nn.functional.cross_entropy` 的误差小于 `1e-6`。

### 模块 B：词表示与经典序列模型

1. 实现 tokenizer 的训练或调用现成 tokenizer；区分训练、编码、解码和 special tokens。
2. 实现 Skip-gram + negative sampling，观察词向量最近邻。
3. 实现一个字符级或词级 RNN/LSTM 语言模型，理解 hidden state、teacher forcing 和 padding。
4. 实现 Viterbi 解码，理解 emission、transition、mask 与回溯路径。

**验收任务**：训练一个小型字符语言模型；给定前缀能采样出合理续写，并能正确屏蔽 padding token 的 loss。

### 模块 C：Transformer 核心

1. 手写 scaled dot-product attention，并支持 causal mask 与 padding mask。
2. 组装 multi-head attention：split heads、transpose、merge heads。
3. 加入 residual connection、LayerNorm、FFN 和 dropout，形成一个 decoder block。
4. 完成位置编码、token embedding、输出投影和语言模型 loss。

**验收任务**：在一个极小语料上训练 mini GPT；确认：

- mask 后的位置不会看到未来 token；
- attention 权重最后一维和为 1；
- loss 能稳定下降；
- 生成阶段逐 token 调用模型且不会把标签泄漏给输入。

### 模块 D：解码、评估与调试

1. 实现 greedy、temperature、top-k、top-p 和 beam search；统一在 **log probability** 空间累积得分。
2. 为 beam search 加入 EOS、长度惩罚、已完成序列保留和 batch 处理。
3. 了解 perplexity、accuracy、precision/recall/F1、BLEU 与 ROUGE-L 各自适用的任务和局限。
4. 训练前先构造 overfit 极小数据集的实验，不能过拟合就先不要扩大训练。

## 4. 推荐的 3 周执行表

| 周期 | 学习重点 | 算法补充 | 产出与验收 |
| --- | --- | --- | --- |
| 第 1 周 | 张量 shape、softmax/logsumexp、cross entropy、Embedding、Skip-gram | LC 72、1143、215 | 手写 cross entropy 对齐 PyTorch；训练词向量并展示最近邻。 |
| 第 2 周 | Tokenizer、RNN/LSTM、Viterbi、Stack/Buffer parser | LC 208、139、20、394 | 写 BPE 演示与 Viterbi；训练字符级 RNN。 |
| 第 3 周 | Transformer block、mask、解码策略与评估 | LC 373、3、76；手写 top-k/top-p | 训练 mini GPT，完成 greedy/top-p/beam 三种生成对比。 |

每天建议遵循一个固定闭环：

1. 读 30–45 分钟概念与公式。
2. 写 60–90 分钟最小可运行代码，并在每行关键张量操作旁标 shape。
3. 用 20–30 分钟写测试：shape、数值范围、mask、梯度或与官方实现的对照。
4. 最后再做 1 道关联算法题，记录“它解决什么工程问题、不能解释什么”。

## 5. 对原有代码模板的工程补充

### Attention

现有注意力示例适合解释 causal mask，但还应补齐：

- `Q` 与 `K` 长度可以不同的情形；
- padding mask 与 causal mask 的组合；
- 全部被 mask 行的数值处理；
- dropout、不同 dtype（尤其半精度）和官方 `scaled_dot_product_attention` 的结果对照。

### Beam Search

建议统一把分数定义为累计负对数概率（NLL）或累计 log probability，变量名与排序方向必须一致。实际解码还需要：EOS 完成态、长度惩罚、屏蔽非法 token、重复惩罚（可选）以及 batch 支持。不要把它当成完整生产级实现。

### BPE

当前循环能解释“统计相邻 pair 并合并”，但实际 tokenizer 还涉及预分词、特殊符号、未知字符/byte fallback、merge 排名与编码阶段。学习时应把“BPE 训练”和“给定 merges 后的编码”分成两个独立任务。

## 6. 最小项目建议

项目名称：**Mini GPT 文本生成器**。

- 数据：一个干净的小文本语料即可。
- 输入：BPE 或字符级 token 序列。
- 模型：2 层 decoder-only Transformer。
- 训练：causal language-model loss，记录 train/validation loss。
- 生成：实现 greedy、temperature + top-p、beam search。
- 报告：保存 3 组生成样例、loss 曲线，以及一张 attention mask 的可视化或打印结果。

完成这个项目后，再回看原题单中的 DP、堆、Trie 和滑动窗口，才能真正建立“算法题—NLP 部件—训练代码”的三层映射。
