## 一、从零开始：什么是“归并”（Merge）？

如果你没听说过“归并”，不要慌，用生活中的例子一秒就能听懂：

### 1. 生活中的“双路归并”
想象两支已经**按照身高从小到大排好队**的小学班级（一班和二班），校长要求把他们合并成一个总的大队伍，依然保持从小到大：
* 做法：两个班的班长站在各自队伍的最前面（双指针）。
* 校长每次只看这两个排头：谁更矮，谁就出列进入总队伍。
* 被挑走排头的那个班级，后面的第二个人自动走上排头位置。
* 这样**一次只比两个人**，直到所有人都合并完。这就是经典的 **双路归并**（Merge Two Sorted Lists）。

### 2. 什么是“多路归并”（Multi-way Merge）？
现在不是 2 个班，而是有 **$M$ 个班**，全都已经按递增排好队了！
校长要挑出所有学生中**最矮的前 $K$ 个人**：
* 此时有 $M$ 个班长站在排头。
* 校长如果每次用肉眼扫描这 $M$ 个人，每次要花 $\mathcal{O}(M)$ 的时间。
* **神器登场——“小顶堆”**！
  * 我们把这 $M$ 个班的排头**全部扔进一个小顶堆**里。
  * 堆顶永远是当前所有人里的**全局最矮**！
  * 校长直接从堆顶挑走一个人（第 1 矮）。
  * 这个人来自哪个班，哪个班的下一个人就立马补进小顶堆中！
  * 重复 $K$ 次，就顺理成章、毫无废步地拿到了**前 $K$ 矮的学生**！

## 二、为什么你的第一直觉（大顶堆）会遇到瓶颈？

在做这道题时，很多同学的第一直觉是：
> “求前 $K$ 个最大，用容量为 $K$ 的小顶堆；那求前 $K$ 个最小，我就维护一个容量为 $K$ 的大顶堆，把所有数对 $(nums1[i], nums2[j])$ 遍历一遍，每次跟堆顶比，更小就换进去。”

这个直觉在逻辑上是**完全成立**的，但它有一个致命死穴——**数据规模（Complexity）**。

* 题目约束：$nums1.\text{length} \le 10^5,\ nums2.\text{length} \le 10^5$。
* 如果你两重 `for` 循环遍历所有的组合：
  $$\text{数对总数} = 10^5 \times 10^5 = 10^{10} \ (\text{100 亿次！})$$
* 现代计算机 CPU 的极限计算速度大约是每秒 $10^8$ 次操作。$10^{10}$ 次操作需要耗时 **100 秒以上**，评测机 1 秒就会报 **TLE（Time Limit Exceeded 超时）**！

**破局的关键：**
题目给了一个巨大的隐藏金矿——**`nums1` 和 `nums2` 本身就是升序排列好的！**
我们根本不需要把 100 亿个数对全看一遍！

## 三、金矿条件：有序矩阵与多路归并模型

假设：
$nums1 = [1, 7, 11]$
$nums2 = [2, 4, 6]$

所有的和可以写成一个二维表格（矩阵）：

| 和矩阵 ($+$) | $nums2[0]=2$ | $nums2[1]=4$ | $nums2[2]=6$ |
| :--- | :---: | :---: | :---: |
| **$nums1[0]=1$** | **3** (1+2) | **5** (1+4) | **7** (1+6) |
| **$nums1[1]=7$** | **9** (7+2) | **11** (7+4) | **13** (7+6) |
| **$nums1[2]=11$** | **13** (11+2) | **15** (11+4) | **17** (11+6) |

仔细观察这个矩阵：
1. **每一行都是单调递增的！**（因为 $nums2$ 是升序的，固定的 $nums1[i]$ 加上越来越大的 $nums2[j]$，和必然递增）
2. 这不就是 $N_1$ 条已经排好序的赛道吗？
   * 第 0 条赛道：$(nums1[0], nums2[0]) \le (nums1[0], nums2[1]) \le (nums1[0], nums2[2])$
   * 第 1 条赛道：$(nums1[1], nums2[0]) \le (nums1[1], nums2[1]) \le (nums1[1], nums2[2])$
   * 第 2 条赛道：$(nums1[2], nums2[0]) \le (nums1[2], nums2[1]) \le (nums1[2], nums2[2])$
3. **我们要求前 $K$ 小，就是求这 $N_1$ 条有序赛道的前 $K$ 个最小元素！**
4. 这正是标准到不能再标准的小顶堆**多路归并**！

## 四、核心算法全流程推演（一步一步带你看懂）

### 1. 结构体设计
每个放入堆里的元素必须记住三样东西：
```cpp
struct Node {
    int sum; // 两数之和 nums1[i] + nums2[j]，用来做堆排序的依据
    int i;   // 当前数对来自 nums1 的哪个下标（第几行/哪条赛道）
    int j;   // 当前数对来自 nums2 的哪个下标（第几列/赛道的第几个）

    // 小顶堆重载 > 运算符：sum 越大的优先级越低（往堆底沉）
    bool operator>(const Node& other) const {
        return sum > other.sum;
    }
};
```

### 2. 动态推演过程（以 $nums1=[1,7,11], nums2=[2,4,6], k=3$ 为例）

#### 【初始化阶段】
把每条赛道的“排头兵”（即 $j=0$ 的元素）扔进小顶堆：
* 赛道 0 排头：$(nums1[0]+nums2[0]=3, i=0, j=0)$
* 赛道 1 排头：$(nums1[1]+nums2[0]=9, i=1, j=0)$
* 赛道 2 排头：$(nums1[2]+nums2[0]=13, i=2, j=0)$
* **此时小顶堆内部**（堆顶是最小的）：`[ (3, 0, 0), (9, 1, 0), (13, 2, 0) ]`

> **优化小细节**：赛道最多只需要取 $\min(n_1, k)$ 条。如果 $k=3$ 而 $n_1=100000$，我们只需要把前 3 条赛道的排头入堆即可，因为第 4 条赛道及以后的所有数对绝不可能挤进前 3 小！

#### 【第 1 次弹出】
* 弹出堆顶：`(3, i=0, j=0)` $\to$ **选出第 1 小数对：$[nums1[0], nums2[0]] = [1, 2]$**
* 赛道 0 的后继者补位：$j+1 = 1 < n_2$，推入 `(nums1[0]+nums2[1]=5, i=0, j=1)`。
* **此时堆内**：`[ (5, 0, 1), (9, 1, 0), (13, 2, 0) ]`

#### 【第 2 次弹出】
* 弹出堆顶：`(5, i=0, j=1)` $\to$ **选出第 2 小数对：$[nums1[0], nums2[1]] = [1, 4]$**
* 赛道 0 的后继者补位：$j+1 = 2 < n_2$，推入 `(nums1[0]+nums2[2]=7, i=0, j=2)`。
* **此时堆内**：`[ (7, 0, 2), (9, 1, 0), (13, 2, 0) ]`

#### 【第 3 次弹出】
* 弹出堆顶：`(7, i=0, j=2)` $\to$ **选出第 3 小数对：$[nums1[0], nums2[2]] = [1, 6]$**
* 已经收集满 $k=3$ 对数字，循环终止！

**最终答案**：`[[1, 2], [1, 4], [1, 6]]`。

### 3. 复杂度对比
| 算法 | 时间复杂度 | 空间复杂度 | $k=10^4$ 时的计算量 | 结果 |
| :--- | :--- | :--- | :--- | :--- |
| 全枚举 + 大顶堆 | $\mathcal{O}(N_1 \cdot N_2 \log K)$ | $\mathcal{O}(K)$ | $10^{10} \times 13 \approx 1.3 \times 10^{11}$ | **严重超时 (TLE)** |
| **小顶堆多路归并** | **$\mathcal{O}(K \log(\min(N_1, K)))$** | **$\mathcal{O}(\min(N_1, K))$** | **$10^4 \times 13 \approx 1.3 \times 10^5$** | **1 毫秒瞬秒通过** |

## 五、重磅延伸：为什么说这道题是 NLP Beam Search 的前置神题？

你马上要学 NLP（自然语言处理）以及大语言模型（LLM）解码生成的基石算法 —— **Beam Search（束搜索）**。
很多同学觉得大模型解码高深莫测，其实它的底层哲学与 LeetCode 373 **完全一致**！

```
                      [自然语言生成与搜索空间]
                      
                           <s> (起始符)
                          /     |     \
                       "我"    "你"   "他"     <- 词表有 50,000 个词 (类似 nums1)
                       /  \    /  \   /  \
                     "爱" "想""是""走""好""看" <- 每一步又有 50,000 种选择 (类似 nums2)
                     ...
```

### 1. 大模型解码的搜索困境
在 Transformer / GPT 生成文本（机器翻译、对话、摘要）时，每个位置从词表（词表大小 $V \approx 50,000 \sim 100,000$）里挑词：
* **贪心搜索（Greedy Search）**：每一步只选概率最高的 top 1。
  * *缺点*：近视眼！这一步选了概率最大的词，可能导致后面整句话走入死胡同（局部最优 $\neq$ 全局最优）。
* **全局暴力搜索（Exhaustive Search）**：遍历所有可能的生成句子。
  * *缺点*：长度为 $L$ 的句子，总路径有 $V^L$ 种。当 $V=50,000, L=20$ 时，计算量比全宇宙的原子总数还多，永远算不完（这就像 LC 373 暴力遍历 $10^{10}$ 个数对一样）。

### 2. Beam Search 的破局之道
Beam Search 设定一个宽度 $B$（Beam Width，束宽，通常取 4 到 8，也就是相当于我们题目的 $K$）：
1. 每一时刻，**只维护当前累计概率最大的 $B$ 条候选路径**。
2. 在扩展下一步时，每条路径衍生出新的可能，形成 $B \times V$ 个候选者。
3. **用优先级队列 / Top-K 堆，瞬间剪枝，只挑出总得分最高的 $B$ 个留给下一步！** 其余非最优分支全部砍掉！

### 3. LC 373 与 Beam Search 的本质契合点
| 核心概念 | LeetCode 373 (多路归并) | NLP Beam Search (束搜索) |
| :--- | :--- | :--- |
| **状态空间** | $N_1 \times N_2$ 组合空间庞大（$10^{10}$） | $V^L$ 句子搜索空间天文数字（指数级爆炸） |
| **剪枝启发** | 数组单调性（利用有序已知条件） | 概率单调递减（只沿高概率分支探索） |
| **数据结构** | **小顶堆（Priority Queue）** 维护当前各分支的头 | **Top-K 堆 / 排序** 维护当前得分最高的最优前缀 |
| **扩展机制** | 弹出 $(i, j)$ 后，**仅按需扩展**其下一个邻居 $(i, j+1)$ | 保留当前 $B$ 个候选后，**仅按需扩展**这 $B$ 个节点的下一步 |

> **一句话总结**：
> 掌握了 LC 373 的“**按需生成候选状态、用堆动态维护当前最优解集、避免盲目枚举全空间**”的精髓，你在看大模型 Beam Search 源码时，就会有一种居高临下、一眼看穿本质的通透感！

## 六、ACM 模式 C++ 完整工程实现与逐行注释

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>

using namespace std;

// 1. 定义堆节点结构体
struct Node {
    int sum; // 数对之和 nums1[i] + nums2[j]
    int i;   // nums1 的下标 (赛道编号)
    int j;   // nums2 的下标 (赛道上的选手位置)

    // 小顶堆重载大于号：sum 大的优先级更低，沉在堆底；sum 小的浮在堆顶
    bool operator>(const Node& other) const {
        return sum > other.sum;
    }
};

// 2. 核心算法函数：多路归并小顶堆
vector<vector<int>> solve(const vector<int>& nums1, const vector<int>& nums2, int k) {
    vector<vector<int>> ans;
    int n1 = nums1.size();
    int n2 = nums2.size();

    // 声明小顶堆
    priority_queue<Node, vector<Node>, greater<Node>> pq;

    // 【第一步：初始化】
    // 最多只需要入堆 min(n1, k) 条赛道的第一个元素 (j = 0)
    // 思考：超过 k 的赛道，其排头都比前面 k 条赛道的排头大，绝不可能成为前 k 小
    int init_limit = min(n1, k);
    for (int i = 0; i < init_limit; i++) {
        pq.push({nums1[i] + nums2[0], i, 0});
    }

    // 【第二步：循环提取前 k 小】
    // 每次循环弹出一个全局最小值，最多弹 k 次（若堆提前空了也结束）
    while (k-- > 0 && !pq.empty()) {
        Node cur = pq.top();
        pq.pop();

        // 收集答案数对 [nums1[cur.i], nums2[cur.j]]
        ans.push_back({nums1[cur.i], nums2[cur.j]});

        // 【第三步：后继补位】
        // 如果当前赛道后面还有元素（j + 1 < n2），把下一个候选人放进堆
        if (cur.j + 1 < n2) {
            pq.push({nums1[cur.i] + nums2[cur.j + 1], cur.i, cur.j + 1});
        }
    }

    return ans;
}

// 3. ACM 模式主函数：标准输入输出与边界格式化
int main() {
    // 提高 I/O 效率
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int n1, n2, k;
    // 多组测试用例循环读取
    while (cin >> n1 >> n2 >> k) {
        vector<int> nums1(n1);
        for (int i = 0; i < n1; i++) {
            cin >> nums1[i];
        }

        vector<int> nums2(n2);
        for (int i = 0; i < n2; i++) {
            cin >> nums2[i];
        }

        vector<vector<int>> ans = solve(nums1, nums2, k);

        // 按照 LeetCode 格式严格打印：[[u,v],[u,v]...]
        cout << "[";
        int total = ans.size();
        for (int i = 0; i < total; i++) {
            cout << "[" << ans[i][0] << "," << ans[i][1] << "]";
            if (i + 1 < total) {
                cout << ","; // 最后一对后面不输出逗号
            }
        }
        cout << "]\n";
    }

    return 0;
}
```
